## 1. 项目概述

### 1.1 项目目标

基于 SM4 国密算法的数据库密码管理系统，提供 6 种集成模式，覆盖主流 Java 技术栈。

### 1.2 技术栈

| 组件 | 技术选择 |
|------|----------|
| **JDK版本** | JDK 8+ (推荐JDK 11) |
| **加密算法** | SM4-GCM 认证加密 |
| **加密库** | Bouncy Castle (1.69+) |
| **JSON库** | Jackson (2.12+) |
| **构建工具** | Maven 3.6+ |

### 1.3 核心设计要点

1. **文件路径屏蔽**: `~/.dbpwd/` 由 `PasswordService` 内部固定，应用无感知
2. **占位符格式**: 使用 `@db_name@` 格式
3. **SM4-GCM 加密**: 认证加密，防篡改
4. **H2 FILE 验证**: 真正的密码验证机制

## 2. 核心设计决策

### 2.1 密码文件格式：JSON结构

采用JSON文件格式存储密码信息：
- 文件路径固定为 `~/.dbpwd/db.pwd`
- 每个数据库条目包含完整的连接信息
- 支持更新时间对比和同步

**选择理由**: 可读性强，易扩展，工具友好

### 2.2 密码字段格式：ENC格式

```
ENC(SM4-GCM:Base64(IV):Base64(密文+标签))
```

**选择理由**: GCM提供认证加密和防篡改功能

### 2.3 占位符格式

应用配置中使用 `@db_name@` 格式的占位符：

```yaml
spring:
  datasource:
    password: "@spring_boot_db@"  # 占位符
```

**说明**: 文件路径由 `PasswordService` 内部固定，应用无需知道文件位置。

### 3.2 设计原则

1. **应用无感知**: 文件路径内部固定，应用只需使用占位符
2. **最小权限**: 文件权限严格设置为600
3. **职责分离**: 运维管理密钥，应用使用密码
4. **可审计**: 所有密文操作记录更新时间

### 3.3 单元测试 vs Demo应用

| 场景 | 文件路径 | 配置方式 | 说明 |
|------|---------|---------|------|
| **单元测试** | 临时目录（@TempDir） | 通过API参数传递 | 自包含、自解释、可隔离 |
| **Demo应用** | `~/.dbpwd/` | 使用默认路径 | 模拟生产环境 |

**单元测试设计原则**:
- 使用 `@TempDir` 注解创建临时目录
- 通过 API 参数传递自定义路径（如 `keyFilePath`, `pwdFilePath`）
- 测试完成后自动清理，不污染用户环境

**Demo应用设计原则**:
- 使用默认路径 `~/.dbpwd/`
- 应用只需使用占位符 `@db_name@`
- 配置文件由运维/初始化工具创建

## 4. SM4密钥管理

### 4.1 密钥文件

| 属性 | 值 |
|------|-----|
| 文件路径 | `~/.dbpwd/sm4.key` |
| 文件权限 | 600（仅所有者读写）|
| 格式要求 | 16字节hex编码（32字符）|

**示例**：
```
AABBCCDD1234567890ABCDEF12345678
```

### 4.2 密钥生命周期

```
密钥生成 → 密钥存储 → 密钥使用 → 密钥轮换
    ↓           ↓           ↓           ↓
 随机生成    写入文件     加载验证    重新加密
 16字节     权限600      格式检查    更新文件
```

### 4.3 密钥保护机制

| 保护机制 | 说明 |
|---------|------|
| 文件权限 | 600权限，仅所有者可读写 |
| 访问控制 | 最小权限原则 |
| 审计日志 | 记录密钥使用和轮换 |
| 备份策略 | 三地备份 |

## 5. 密码更新流程

### 5.1 密码更新步骤

```
1. 前置准备
   - 备份当前db.pwd文件
   - 确认新密码强度

2. 更新数据库实际密码

3. 加密新密码
   - 使用SM4密钥加密
   - 生成ENC(SM4-GCM:...)格式

4. 更新密码文件
   - 更新password字段
   - 更新updatedAt时间戳

5. 同步到配置中心

6. 应用程序同步

7. 验证和监控
```

### 5.2 密码更新命令

```bash
# 交互模式更新密码
dbpwd-cli update db001

# 测试密码更新后连接
dbpwd-cli test db001
```

## 6. 设计决策总结

### 6.1 核心设计原则

| 原则 | 说明 |
|-----|------|
| **应用无感知** | 文件路径固定为 ~/.dbpwd/ |
| **最小权限** | 文件权限600 |
| **职责分离** | 密钥与密码分开管理 |
| **可审计** | 记录所有敏感操作 |

### 6.2 关键技术选择

| 技术点 | 选择 | 理由 |
|-------|-----|------|
| 加密算法 | SM4-GCM | 国密标准，认证加密 |
| 占位符格式 | @db_name@ | 明确标识 |
| 文件路径 | ~/.dbpwd/ (固定) | 参考SSH机制 |
| 文件格式 | JSON | 可读性强，易扩展 |

### 6.3 安全性评估

| 安全维度 | 评级 | 说明 |
|---------|-----|------|
| 密钥保护 | ⭐⭐⭐⭐⭐ | 600权限 + 应用无感知 |
| 传输安全 | ⭐⭐⭐⭐⭐ | 本地文件存储 |
| 访问控制 | ⭐⭐⭐⭐⭐ | 最小权限原则 |

### 6.4 架构优势

1. **高安全性**: SM4-GCM认证加密，应用无感知文件路径
2. **高可用性**: 应用与配置中心解耦
3. **易维护性**: JSON格式可读，占位符简洁
4. **易扩展性**: 支持6种集成模式
